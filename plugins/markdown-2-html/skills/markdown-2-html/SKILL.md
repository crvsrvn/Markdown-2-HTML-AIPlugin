# Markdown-2-HTML

本规范是用户对文档读写方式和 HTML 样式的明确约定：

- 用户在当次请求里给出的不同要求，优先于本规范。
- 本规范优先于通用设计建议（例如 artifact-design 里关于字体、配色、版式的默认建议）。

## 核心约定

| 项 | 要求 |
|----|------|
| 源文件 | 文档的唯一真值是 `.md`（UTF-8）。AI 只读写 `.md`，按 [references/syntax.md](references/syntax.md) 的语法写 |
| 生成的 HTML | 只给人阅读。AI 不读取、不 grep、不修改、不当作上下文，也不在浏览器里打开查看，除非用户明确要求。需要内容时读它 `<meta name="m2h-source">` 指向的 `.md`（Claude Code 里有 hook 强制拦截） |
| 识别方式 | 生成的 HTML 的 `<head>` 里有 `<meta name="generator" content="Markdown-2-HTML/版本">`。没有这个标记的 HTML 不受本约定限制 |
| 导出时机 | 文档定稿后，或用户要求时，才导出 HTML；写作过程中用 `check` 检查能否导出 |
| 不手写 HTML | 序号、锚点、大纲、提示块图标、状态标签颜色、代码高亮、图表缩放、表格全屏都由导出工具生成 |
| 交付 | 导出的单文件 HTML 双击即可打开，不依赖任何外部服务（字体加载失败时回退到本机字体）。把 HTML 路径告诉用户，由用户分享。不默认发布到 Artifact |

## 命令

`<本技能目录>` 是加载本技能时给出的 Base directory。只需要 Node.js 18+，无需安装依赖。

```bash
node "<本技能目录>/scripts/dist/m2h.mjs" check  doc.md                 # 写作中：检查语法、页内链接、PlantUML
node "<本技能目录>/scripts/dist/m2h.mjs" build  doc.md [-o out.html]   # 定稿：导出（默认同目录同名 .html）
node "<本技能目录>/scripts/dist/m2h.mjs" migrate page.html doc.md [--puml-dir <目录>]   # 旧版 html-style 页面 → Markdown
node "<本技能目录>/scripts/dist/m2h.mjs" verify 原页面.html 导出页面.html            # 迁移后逐项比对语义内容
```

导出失败时，错误信息会指出原因（未知提示块类型、不存在的页内链接、PlantUML 语法错误等），改 `.md` 后重试。

## 写作规范

沿用 html-style 的阅读规范，用 Markdown 语法表达：

- **标题**：一个 `#` 一级标题；章节用 `##` `###`（`####` 需在文件头 `toc: [2, 3, 4]` 才进大纲）。不写序号，导出时自动编号；不加图标。
- **强调**：加粗与高亮二选一，同一处不叠用。术语、关键词用 `**加粗**`；需要一眼扫到的结论句用 `==高亮==`。
- **提示块**：说明、建议、注意事项、风险、结论要点写成 `> [!warn] 注意`，标题 2–4 个字；只用于需要读者停下来的段落，一屏内不超过两个。
- **状态标签**：表格状态列、优先级、段落里的状态词写成 `:ok[完成]`。语义固定：完成 / 已修 / 已有 → `ok`；新增 / 保留 → `info`；未做 / 未实现 / 中优先级 → `warn`；删除 / 缺口 / 高优先级 → `danger`；不变 / 同上 / 无 → `muted`。
- **图例记号**：文档自定义的分类符号在文件头 `marks` 声明一次含义，正文写 `:m[实]`。
- **编号**：需求、缺口、决策编号写成行内代码 `` `RT-01` ``，导出时同前缀同色。
- **交叉引用**：写 `[](#s4-1)`，导出时自动填目标序号，不要手写“见 4.1”。
- **折叠**：只用于次要内容（附录、推导、长清单）。代码超过 25 行自动折叠；结论、关键数据不折叠。
- **表格**：首行是表头；表格标题写在表格正上方 `Table: 标题`。
- **图表**：用 PlantUML 源码（```` ```plantuml ````），导出时渲染成 SVG，可拖动缩放、双击全屏。多张图共用的 skinparam 放进 ```` ```plantuml-include ```` 块。颜色必须编码含义，不做纯装饰。文档之外单独画图（回答里配图、导出 SVG）用 plantuml 技能。
- **数据密集的页面**：同类条目用 ```` ```records ````，按年份 × 分类之类的计数表用 ```` ```heatmap ````，正文只写数据。

## 工作流程

### 新建或修改文档

1. 读写 `.md`。修改已有文档时，先读 `.md` 的最新内容，基于它改。
2. 写作中可随时运行 `check`。
3. 定稿后运行 `build`，把导出的 HTML 路径告诉用户。之后 `.md` 每次修改都要重新 `build`，不要手改 HTML。

### 只有 HTML、没有 Markdown 时

- 是本插件生成的 HTML：找它 `m2h-source` 指向的 `.md`；找不到时告诉用户缺少源文件，不读 HTML。
- 是旧版 html-style 页面（没有生成标记）：用 `migrate` 转成 `.md`，再 `build`，用 `verify` 比对原页面与新导出页面，差异逐条处理或说明。图里没有内嵌 PlantUML 源码时，用 `--puml-dir` 指向源文件目录。

## 交付前自检

- [ ] 只读写了 `.md`，没有读取或修改生成的 HTML。
- [ ] `check` 通过；定稿时已 `build`，HTML 路径已告诉用户。
- [ ] 标题没有手写序号；交叉引用用 `[](#id)`。
- [ ] 加粗与高亮没有叠用；提示块、状态标签、图例记号、编号按语义使用。
- [ ] 图表是 PlantUML 源码，没有嵌入 base64 图片。
